# cvin-combined — ERC-1056 + ERC-735 hybrid (plan S7 demos)

**Identity model.** One shared `CVINCombinedIdentity` registry in which every address is an identity (ERC-1056 side: `identityOwner` defaults to self, event-only attributes, stored time-bound delegates, a `changed` pointer) and the same `identityOwner` gates an ERC-735-style on-chain claim store for the safety-critical subset (VIN, manufacturer/type approval, inspection) whose issuer signature is verified at `addClaim` time so contracts can later check `hasValidClaim`/`getClaim` in O(1). Creation is implicit (0 gas); no meta-transactions and no identity-level revocation. Since the 2026-10-06 merge (K-6, decision M-A) claim operations no longer advance the ERC-1056 `changed` pointer — claims are not DID-document state — and an issuer can revoke its signed content for good (`revokeClaimContent`, K-2).

Run: `cd 1_blockchain-identity && npx hardhat run ../sandbox/options/cvin-combined/demos/<family>.js`. 152 steps, 63 mined transactions (10 of them the per-demo registry deployment) across the ten demos.

## Asymmetry notes

- **Creation: implicit** (0 gas) — a factory can generate the key and the OEM can sign the VIN claim before the vehicle ever touches the chain; the first transaction may already be a trusted-claim anchoring. The comparison labels the first `setAttribute` as createIdentity.
- **Veracity / automation.** Chain enforces: one controller for both halves, delegate validity (`validDelegate`), **issuer signature validity and binding to (registry, identity, topic, data)** at `addClaim`, holder consent, per-claim removal rights, **issuer-side sticky revocation** (`revokeClaimContent` marks `revokedClaims[keccak256(issuer ‖ digest)]`, after which no controller can re-anchor that signed content; K-2). On-chain verifiers get O(1) answers (`hasValidClaim`, `validDelegate`, `getClaim`) for the safety-critical subset; everything else (keys, services, attributes) needs an off-chain event replay. Not enforced: issuer accreditation (any key can issue a manufacturer claim), claim expiry (`hasValidClaim` = "present"; since K-11 it returns false for `issuer = address(0)`, a path no demo exercises), VIN uniqueness, identity-level revocation, signature malleability.
- **Cryptography / hashing.** `claimId = keccak256(issuer ‖ topic)`; claim digest `keccak256(abi.encodePacked(registry, identity, topic, data))` signed as a **raw secp256k1 digest, no EIP-191 prefix** (mirrors ERC-1056 meta-tx signing; HSM/signingKey, not personal_sign) — the opposite convention of the ERC-735 claim holder, so the two are signature-incompatible (demonstrated both ways). Attribute names/delegate types are `keccak256` strings. No nonce, no meta-transactions.
- **Implemented but not compared.** Delegate expiry, attribute revocation, issuer-side claim withdrawal, issuer-side content revocation (`revokeClaimContent`/`revokedClaims`), in-place claim re-add, `hasValidClaim` as an on-chain gate, VIN anchoring as a claim, the two verification paths in one identity.
- **Observed defects / surprises.** *Fixed 2026-10-04, revised 2026-10-06 (merge: K-6, decision M-A) — D22 (`docs/DEFECT_LOG.md`); `controller.js` and `lifecycle-history.js` assert it and mark the steps `FIXED (K-6 / M-A)`:* `addClaim`/`removeClaim` no longer advance `changed` (the pointer stays on the last DID event), and they still emit `DIDClaimChanged(identity, claimId, topic, removed, previousChange)` next to `ClaimAdded`/`ClaimRemoved`, with `previousChange` = the DID chain head at the time of the claim operation. A did:ethr-style walk therefore visits the DID events only, reaches genesis and is never cut by a claim block; the claim history is read from its own identity-indexed `DIDClaimChanged` filter and merged by block (the adapter's range-scan fallback stays idle). *Fixed 2026-10-06 (merge: K-2):* an owner-side `removeClaim` is not a revocation (the controller can re-anchor the issuer's old signature), but the issuer's `revokeClaimContent` is sticky: it removes the anchored copy and makes any re-anchor of that signed content revert "claim revoked by issuer", whoever the controller is (`controller.js`). *Still open:* `revokeDelegate` leaves the timestamp in storage (no refund, resolver must test `<= now`); re-adding a claim emits `ClaimAdded` (no `ClaimChanged`); no EIP-2 low-s guard (D22 rest; K-2 keys revocation on the signed digest, so a malleated copy of revoked content is blocked, but a malleated signature is still stored verbatim); `changeOwner(id, 0)` restores self-control (D26); revoking a never-set attribute succeeds; no identity-level revocation at all (the vehicle-profile registry has one).

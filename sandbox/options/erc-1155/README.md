# ERC-1155 — feature demos (plan S7)

**Identity model.** Each ERC-1155 token id is a *credential type* (1 BIRTH_CERT, 2 REGISTRATION, 3 INSPECTION_CERT, 4 INSURANCE_CERT, 5 MAINTENANCE_BADGE — any other id up to `MAX_CREDENTIAL_TYPE` = 255 is accepted too); a vehicle is the *address* that holds one soulbound BIRTH_CERT, indexed by `vehicleVIN` (address → VIN) and `vinHashToVehicle` (keccak256(VIN) → address). All writes require `ISSUER_ROLE`, and the standard `safeTransferFrom`/`safeBatchTransferFrom` entry points revert for everyone (D7 fix); holders can only receive, so a controller change is an issuer re-binding the identity to a new address — `issuerTransferIdentity` moves the BIRTH_CERT together with every held credential type (one `TransferBatch`, `IdentityRebound` event), `issuerTransferCredential(BIRTH_CERT)` moves a bare identity (the identity address itself changes, which is why the adapter uses the VIN hash as the id).

Run one demo: `cd 1_blockchain-identity && npx hardhat run ../sandbox/options/erc-1155/demos/<family>.js`. `demos/_lib.js` is the shared step printer. 185 steps, 57 mined transactions.

## Asymmetry notes

- **Creation: minted.** `registerVehicle` by an issuer mints the BIRTH_CERT (104 k gas in L1). The VIN is upper-cased and ISO 3779-checked (17 chars, no I/O/Q; check digit not enforced) since the D13 fix — a 5-character or lower-cased-twin VIN is rejected. Deregistration is reversible: the same VIN can be registered again later.
- **Veracity and automation.** The chain enforces the issuer role on every write and transfer, BIRTH_CERT uniqueness per address, VIN-hash uniqueness, the receiver hook, and (since D8) the structural invariants — a non-BIRTH credential is only ever held by a registered vehicle, a BIRTH_CERT is only burned or moved alone when nothing else is held, credential types are 1..255; it enforces nothing about *content*: a credential is `(address, type, amount)` with no issuer, date, expiry or subject stored, so "revoked" and "never issued" read identically and a credential from a since-revoked issuer stays valid. A verifier must replay `CredentialIssued`/`CredentialRevoked` logs to learn who issued what and when, and read the (collection-wide) `uri` documents off-chain; `credentialTypesOf` at least tells it *which* types to look at. `setTokenURI` now also emits the standard ERC-1155 `URI` event (D8), and a sale is one `TransferBatch` plus `IdentityRebound`, so generic indexers see both.
- **Cryptography / hashing.** `keccak256(bytes(normalised vin))` is the only hash (the uniqueness index; the plain upper-cased VIN is also stored and logged); `vinHashOf`/`vehicleForVIN` normalise on-chain, while the raw public mapping getter `vinHashToVehicle` takes whatever hash the caller computed and cannot. Role ids are `keccak256("ISSUER_ROLE")`. No signatures anywhere — authorisation is `msg.sender` + role.
- **Implemented but never compared.** Batch reads (`balanceOfBatch`; the standard `safeBatchTransferFrom` exists only as a soulbound revert), the batch sale `issuerTransferIdentity` (its cost grows with the number of held types, so the benchmark keeps measuring the bare-BIRTH_CERT `issuerTransferCredential`), `credentialTypesOf` / `MAX_CREDENTIAL_TYPE`, receiver hooks on contract recipients (reached only through the issuer paths), operator approvals (inert: the standard entry points revert before the approval rule runs), credential types 2/4/5 and multi-unit (fungible) issuance, `hasCredential`, `renounceRole`/`getRoleAdmin`, and the self-transfer guard.

## Coverage check

Union of functions exercised across the nine demos vs the public/external ABI: **CVINVehicleCredential1155 34/34 — no uncovered function** (`vinHashOf` and `vehicleForVIN` were added by the D13 fix and are exercised by `vin-linkage.js`; `issuerTransferIdentity`, `credentialTypesOf` and `MAX_CREDENTIAL_TYPE` were added by the D7/D8 fix and are exercised by `controller.js`, `claims.js`, `revocation.js`, `lifecycle-history.js` and `authorisation-roles.js`).

Behaviour worth flagging. *Fixed 2026-10-04 — D13 (`docs/DEFECT_LOG.md`), `creation.js` and `vin-linkage.js` assert it and mark the steps `FIXED (D13)`:* VINs are normalised and ISO 3779-checked at registration, so the lower-cased twin and malformed VINs are rejected. *Fixed 2026-10-04 — D7/D8, `controller.js`, `revocation.js`, `claims.js` and `attributes.js` assert it and mark the steps `FIXED (D7)` / `FIXED (D8)`:* the standard `safeTransferFrom`/`safeBatchTransferFrom` revert for everyone (the issuer-as-operator path that moved the BIRTH_CERT without re-binding `vehicleVIN`/`vinHashToVehicle`, and later aliased `keccak256("")`, is gone); `issuerTransferIdentity` moves the BIRTH_CERT with every held type in one `TransferBatch`, re-binds both indexes and emits `IdentityRebound`; `issuerTransferCredential` delivers a non-BIRTH type only to a registered vehicle and moves the BIRTH_CERT alone only from a vehicle holding nothing else; `revokeCredential(BIRTH_CERT)` refuses while other credentials are held (no orphans); `issueCredential` rejects types above 255 and `credentialTypesOf` enumerates the held set; `setTokenURI` emits the standard `URI` event. *Still open (documented, not changed — `claims.js` `any-issuer-revokes` and `authorisation-roles.js` `dmv-revokes-insurance`):* `ISSUER_ROLE` is one flat role, so any issuer may revoke another issuer's credential and the chain cannot tell issuers apart by competence; deregistration is reversible (the same VIN can be registered again); `setTokenURI` accepts any id; `RoleAdminChanged` is never emitted.

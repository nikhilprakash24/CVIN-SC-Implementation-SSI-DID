Twelve months of written research ran as parallel lanes in a project knowledge store (168 filed documents at the freeze) and, from September, a hub repository (nikhilprakash24/cvin-sc, private). This map shows where each lane stands, where it enters the unified seven-chapter thesis ruled on 30 October (D-R9), and what is filed, what sits only in the hub, and what still lives only in chat. The code-side map does the same for the branches; the two maps meet in Chapter 6 and in the numbers-of-record rule.

Three things to know first

One thesis, two spines until 30 October

The hub holds a specification-first thesis (five chapters, ≈60,200 prose words, RQ1–RQ3); the code side holds a benchmark-first thesis (seven chapters, ≈45,000 words, RQ1–RQ5, H1–H6). The same labels mean different questions on the two sides. Ruling D-R9 adopted one unified outline on the hub spine with the applied system as Chapter 6 and the code side's questions as sub-questions. Nothing sent to a supervisor should present either side as "the thesis" alone.

The numbers of record are the hub's, for the interface

Interface gas per function is the Lineage A protocol matrix (N = 5, D-R8, 128/128 cells); deployment gas the N = 5 run of 2026-10-23; createPresentation 62,458. The code side's native-analogue gas is admissible only as indicative, different toolchain, in its own table. Test counts are stated per suite with date and commit (133 sandbox; 564 + 376 spoke) and never summed with the September 201.

61 output sets are unfiled

The chapter drafts of Sessions B–F, the Thesis-B trunk, the CEV ledger v2.0, the Narrative Spine, CORE 3, the closure contribution and the T-1/ISB/cost thread outputs exist in chat only (unfiled register v0-2; 21 at priority 0). Take 1 had to reconstruct ten sections by description for that reason. Filing them (D-18) is the one-hour task everything after depends on.

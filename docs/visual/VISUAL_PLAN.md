## 0. Read this first (one screen, plain words)

A simulation is a running program. On paper it has to become **still pictures that
can be trusted**. The rule of this plan is simple:

> **Data first, pictures second, pretty last.**
> Every picture is drawn from an event trace the program itself wrote, with the
> seed and the run conditions printed under it. If a picture cannot be
> regenerated from a trace file with one command, it is not in the thesis.

What now exists (built and run in this session, all on the branch):

| Layer | What it is | Where |
|---|---|---|
| **Data** | The simulation writes a JSON-Lines *event trace*: every vehicle position, every signed broadcast, every receiver-side verification (cold / warm / rejected, with its measured latency), every safety and attack event. | `--trace` flag on `cv2x-testbed/sumo/sumo_identity_integration.py`; traces in `docs/visual/traces/` |
| **Still figures** | Six figure types (F1–F6) rendered from a trace, each with a provenance footer. | `cv2x-testbed/sumo/viz/thesis_figures.py` → `docs/visual/figures/<trace>/` |
| **Interactive** | A single-file replay viewer: play, scrub, step, click a vehicle for its DID / VIN card, live counters, FCW / EEBL / attack log. | `docs/visual/replay/replay.html` |
| **Real SUMO** | The network was rebuilt so real SUMO loads it; TraCI mode runs; SUMO-GUI runs headless and saves frames with vehicles painted by identity layer. | `cv2x-testbed/sumo/net_src/`, `gui_settings.xml`, `docs/visual/sumo_frames/` |

The rest of this document is the plan: what we can do now, what would be awesome,
the exact shot list, the style, and prompts for image tools where a generated
illustration is the right tool.

## 1. Ground truth before art: what is real, what is mock, what the pictures may claim

Readers of a thesis will ask "what am I looking at?" before "is it pretty?". Every
visual must answer with the same confirmations the README makes:

| Element in a picture | Real or mock | What a caption may say |
|---|---|---|
| Signing of each BSM | **Real** (ECDSA P-256 for PKI, secp256k1 EIP-191 for SSI) | "each message is actually signed" |
| Receiver-side verification, cold and warm | **Real** (X.509 chain + CRL + ECDSA; W3C VC verification + signature recovery) | "every link drawn is a verification that ran" |
| Latency numbers on any axis | **Real**, `time.perf_counter` around the cryptographic call | "compute latency of identity verification only" |
| Attack rejections | **Real**: computed by the verifier, not asserted | "pass/fail is computed" |
| Vehicle motion in `--simulate` | **Mock** kinematic model (5 km, 3 lanes) | must say "mock mobility" |
| Vehicle motion in TraCI mode | **Real SUMO** car-following on the regenerated network | may say "SUMO 1.28 mobility" |
| Radio channel | **Mock**: in-process delivery, ≤8 nearest within 300 m, no loss, no MAC delay | must say so in every latency figure |
| The blockchain | **Not in the loop** during V2V: credentials are verified off-chain; the chain figures live in chapter 5's gas tables | never imply a chain read per message |

The two modes exist for a reason and both are kept: `--simulate` is the
reproducible, dependency-free run the N=30 statistics come from; TraCI mode is
the "it runs on real SUMO" confirmation. Figures say which one they come from
in the footer.

### Confirmations made in this session (things that were not true before)

1. **The committed SUMO network did not load.** `highway_intersection.net.xml`
   was hand-written pseudo-XML (node/edge/connection tags mixed into a `<net>`);
   SUMO 1.28 rejected it ("Shape of lane … broken", "Unknown from-node"). It is
   now generated by `netconvert` from `net_src/*.nod.xml` + `*.edg.xml`
   (same edge ids, so `routes.rou.xml` is unchanged in meaning). The route file
   needed departure-time sorting, also fixed. **Every earlier "SUMO" claim was in
   fact `--simulate` fallback**; the README's "with SUMO installed" path had never
   executed. This belongs in `docs/SCOPE_CHANGES.md` as a confirmation, not a
   scope change: the results of record were always labelled `--simulate`.
2. **TraCI mode runs end to end** (`pip install eclipse-sumo`, 1.28.0): 60 s,
   26 vehicles, 8,433 signed broadcasts, 46,363 verifications, 7/7 attacks
   rejected. Latencies match the `--simulate` numbers within the same order
   (SSI warm median 0.26 ms vs 0.23 ms; cold 0.73 vs 0.58 ms) — the identity
   layer does not care where the positions come from, which is experiment S1 of
   `docs/PLAN_MOBI_SUMO.md` answered qualitatively; the N=30 version is Phase 1.
3. **SUMO-GUI frames can be captured unattended** (Xvfb + `traci.gui.screenshot`,
   1600×900), with vehicles coloured by identity layer over TraCI and the view
   tracking a chosen vehicle. Vehicle glyphs are still small at road scale; the
   GUI scheme needs one more pass (Phase 4).
4. **The pictures found something.** F2 (contact matrix) shows PKI peers
   re-entering *cold* every ~10 s: the pseudonym certificate rotates every 100
   messages, so every neighbour pays the full chain check again at each
   rotation, while an SSI peer's DID binding is verified once per encounter.
   That is a real architectural difference the tables did not show. It needs a
   sentence in chapter 6 and a register row if it is quantified.

## 4. Style guide — "academic urban"

The line to walk: a thesis examiner must find nothing to object to in a data
panel; a reader should still feel a hand behind the pictures. The way to hold
both is **two registers**:

1. **The data panel is formal.** Axes with units, n on every series, log scale
   labelled, legends in words, a provenance footer (trace file, mode, seed,
   duration, rate, radius). Nothing decorative touches the plotting area. Colour
   never carries meaning alone: every class is also named in the legend or label.
2. **The title block carries the voice.** A short stencil-case title in a
   monospace face (`THE ROAD AT T = 15.0 S`, `VERIFY ONCE, CHECK EVERY MESSAGE`,
   `ATTACK BOARD`), a one-line subtitle in plain prose, and at most one *stamp*
   (`REJECTED`) where the result is categorical. That is the whole Banksy budget:
   a stencil and one spray colour, used for alerts only.

**Palette** (shared by the figures, the replay and the SUMO scheme):

| Role | Hex | Use |
|---|---|---|
| paper | `#fcfcfb` | background everywhere |
| ink | `#0b0b0b` | titles, cold links |
| ink-2 / muted | `#52514e` / `#898781` | labels, footers |
| SSI / MOBI VID | `#2a78d6` | the blue; vehicles, series |
| PKI | `#c99228` | the ochre; vehicles, series |
| warm | `#9a9890` | cached signature checks (thin) |
| rejected | `#d03b3b` | failed verifications (dashed) |
| spray | `#ff3d00` | budgets, FCW/EEBL, stamps — never for a data series |

Blue vs ochre is distinguishable for the common colour-vision deficiencies and
prints in greyscale as two different lightnesses; the legend names them anyway.

**Typography:** DejaVu Sans for the panel, DejaVu Sans Mono for titles and
stamps. Both ship with matplotlib so the figures render identically on any
machine; the thesis body font stays whatever the template says.

**What is not allowed in a chapter figure:** textures, drop shadows, spray
splatter in the plotting area, numbers typed in by hand, a colour whose meaning
is not in words, a screenshot of a live window with UI chrome, any image a
generator produced presented as a result. Generated illustrations may open a
chapter and must be captioned "illustration".

## 5. Validation rules (so a visual can be cited)

1. **One command regenerates it.** The command is in the caption source file or
   the phases doc, and uses only files on the trunk.
2. **The footer is the provenance.** Trace name, mode, seed, duration, rate,
   radius, receivers-per-broadcast; the renderer writes it, nobody types it.
3. **Counts in the title come from the trace.** The subtitle says "31 broadcasts,
   107 verifications" because it counted them.
4. **The results of record are untouched.** Traced runs write `--results` to a
   scratch path; `results/v2v_latency.json` changes only through the N=30 driver.
5. **A figure that shows a number from the register cites the row** (#27 for
   latency, the attack rows for F4).

## 7. Known gaps and risks

- **GUI vehicle size: fixed.** The 1.28 attribute is `vehicle_exaggeration`, not
  `vehicleExaggeration`. At 6× and zoom 400 a car is readable in a 1600×900 frame.
- **FCW is highway-only.** It uses "ahead = larger x", so the simulation now
  returns no FCW for lanes not named `highway*`. Chapter 4 should state FCW is
  evaluated on the highway edges.
- **Cold verifications cluster at highway entry, not at the intersection.** The
  cold map from the 60 s TraCI run (`figures/sumo_coldmap/`) puts first contacts
  near x = 0, where vehicles are inserted. Few vehicles reach the junction in
  60 s. The intersection hypothesis in Rung 3 needs a longer run (≥ 200 s) or
  insertion closer to the junction before it can be claimed.
- **Trace size.** ~300 events per simulated second at 30 vehicles. Fine for 60 s;
  for a 300 s run thin snapshots with `--trace-every 5` (figure counts stay exact).
- **Replay in file:// mode** needs the file picker (browsers block fetch); the
  embedded build in Phase 3 removes that step.
- **Nothing here changes a result of record.** The two committed traces were run
  with `--results` pointed at scratch; `results/v2v_latency.json` is unchanged.

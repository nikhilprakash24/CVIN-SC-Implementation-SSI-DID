## contract `ZkVinGate`

**ZkVinGate** · CVIN research project

Identity-dependent transaction gate: admits an action for an ERC-1056 identity only with a zero-knowledge proof of knowing the opening (VIN, model year, region, salt) of the identity's anchored Poseidon commitment.

*Dev:* The ZK-VIN circuit (circuits/zkvin.circom, ZkVin(4)) proves: Poseidon(packedVIN, modelYear, region, salt) equals the commitment; the VIN's WMI is a leaf of the authorised-manufacturer Merkle tree (depth 4); modelYear >= minModelYear; region matches; nullifier = Poseidon(salt, scope). The gate checks every public signal against on-chain values, enforces one nullifier per scope, then calls the Groth16 verifier. Hides the VIN, exact model year and manufacturer; the identity itself is public (no anonymity set). Closes gap AR-5 of docs/phase2/focus/F1_onchain_storage_idtx/ANALYSIS.md. Deviations from the header text: `governor` and `mfrRoot` are fixed at deployment and services cannot be deactivated.

- **standard:** Groth16 (J. Groth, "On the Size of Pairing-based Non-interactive Arguments", EUROCRYPT 2016, https://eprint.iacr.org/2016/260)
- **standard:** EIP-196 alt_bn128 add/mul precompiles (https://eips.ethereum.org/EIPS/eip-196)
- **standard:** EIP-197 alt_bn128 pairing precompile (https://eips.ethereum.org/EIPS/eip-197)
- **standard:** EIP-1108 alt_bn128 gas repricing (https://eips.ethereum.org/EIPS/eip-1108)
- **standard:** ERC-1056 Ethereum Lightweight Identity (https://github.com/ethereum/EIPs/issues/1056)
- **standard:** Poseidon hash (https://eprint.iacr.org/2019/458)
- **security:** Verifier keys come from an INSECURE single-party trusted setup with fixed entropy (circuits/build_circuit.sh): anyone can forge proofs. Research artefact only.
- **security:** `action` and `serviceId` are not bound into the proof: a mempool observer can front-run `admit` with the same proof and a different action (or a service with identical parameters), spending the nullifier.
- **security:** `challenge` is static per service (a session parameter, not a fresh nonce); replay is stopped only by the nullifier.
- **security:** A nullifier is never cleared: one admission per (salt, scope); a second needs re-anchoring with a new salt.
- **security:** No AR-6 equivalent: after an ERC-1056 ownership transfer the previous owner's commitment stays valid until the new owner re-anchors.
- **security:** Groth16 proofs are malleable; replay protection is correctly keyed on the nullifier, not on proof bytes.
- **see:** docs/smart-contracts/05-zkp-and-idtx.md (section 3.3)
- **see:** 5_zkp-agent-identity/test-contracts/zkvin_gate.test.js

#### `admit`

```solidity
function admit(address identity, bytes32 serviceId, uint256[2] a, uint256[2][2] b, uint256[2] c, uint256[7] pub, bytes32 action) external
```

Admits `identity` to `serviceId` given a valid ZK-VIN proof; callable by anyone (owner, agent, relayer).

*Dev:* Checks, in order: service active; pub[1] equals the non-zero anchored commitment; pub[2..6] equal mfrRoot, minModelYear, region, scope, challenge; nullifier fresh in scope; verifier accepts.

## contract `CVINVehicleLSP8`

**CVINVehicleLSP8** · CVIN research project

LSP8-style vehicle identity: one bytes32 token per vehicle (keccak256 of the normalised VIN) with a per-token key/value store; the contract owner is the issuing authority.

*Dev:* Minimal, self-contained LSP8-flavored (LUKSO LSP8 Identifiable Digital Asset) vehicle identity contract for the CVIN thesis gas comparison. Does NOT import the LUKSO lsp-smart-contracts npm package. Model: each vehicle is a non-fungible token identified by bytes32 tokenId = keccak256(bytes(VIN)) with an LSP8-style per-token key-value metadata store (setDataForTokenId / getDataForTokenId, DataChanged event). ============================================================================ REPRESENTATIVE IMPLEMENTATION — LSP8 feature coverage ============================================================================ Implemented (LSP8-conformant signatures/semantics):

- bytes32 tokenIds (LSP8_TOKENID_FORMAT: hash of the VIN)
- totalSupply(), balanceOf(address), tokenOwnerOf(bytes32), tokenIdsOf(address)
- transfer(address from, address to, bytes32 tokenId, bool force, bytes data)

with the LSP8 Transfer event shape (operator, from, to, tokenId, force, data)

- mint via mintVehicle() and burn/revoke via revokeVehicle() emitting

Transfer from/to the zero address

- setDataForTokenId(bytes32,bytes32,bytes) / getDataForTokenId(bytes32,bytes32)

and batch variants, emitting TokenIdDataChanged(tokenId, dataKey, dataValue) (LSP8's event name; a generic DataChanged is emitted as well for tooling) OMITTED relative to the full LSP8 standard (intentional — this contract is a representative implementation for gas benchmarking, not a spec-complete one):

- LSP1 UniversalReceiver hooks: no _notifyTokenSender/_notifyTokenReceiver

calls; the `force` flag is accepted but only checked against code-less recipients (no LSP1 interface probing).

- Operator management: authorizeOperator / revokeOperator / isOperatorFor /

getOperatorsOf are not implemented; only the token owner (or the contract owner for revocation) can move a token.

- ERC725Y contract-level data store (setData/getData on the collection) and

LSP4 DigitalAssetMetadata keys.

- ERC-165 interfaceId registration for LSP8 (0x3a271706).

Access model: contract `owner` = issuing authority (mints, revokes, writes token metadata); token owner = current vehicle owner (transfers the vehicle). ============================================================================ Extensions beyond LSP8: generic DataChanged event without tokenId, mintVehicle/revokeVehicle, token-owner burn, hand-written owner/transferOwnership (no renounce), generation-scoped data (REVIEW_02 K-8). Data keys are plain keccak256("CVIN_...") strings, not LSP2-encoded keys. No dependencies are imported (not built on npm lukso/lsp-smart-contracts ^0.14.0 or OpenZeppelin).

- **note:** The model line above says tokenId = keccak256(bytes(VIN)); since D13 it is the keccak256 of the NORMALISED (upper-cased) VIN, see tokenIdForVIN.
- **standard:** LUKSO LSP8 Identifiable Digital Asset (representative subset) https://docs.lukso.tech/standards/tokens/LSP8-Identifiable-Digital-Asset
- **standard:** ERC725Y-style key/value data (style only) https://docs.lukso.tech/standards/erc725
- **security:** force=false only checks that the recipient has code (no LSP1 probing); mint and burn always use force=true.
- **security:** No operators: marketplaces or agents cannot move a token on the owner's behalf.
- **security:** DataChanged carries no tokenId and is ambiguous across tokens.
- **security:** After revoke the old data stays in storage and past events; only the getter hides it.
- **security:** tokenId is derived from the VIN alone, so anyone who knows a VIN can compute it.
- **security:** The token owner can burn their own identity.
- **see:** docs/smart-contracts/03-token-standards-erc721-erc1155-lsp8.md
- **see:** sandbox/options/lsp8/adapter.js

## contract `ERC1056Registry`

**ERC1056 DID Registry for Connected Vehicles** · CVIN research project

Shared ERC-1056 ("vehicle profile") DID registry: any address is a did:ethr identity, with owner, delegate and attribute changes published as events, plus a terminal identity revocation.

*Dev:* Lightweight Ethereum DID Registry (ERC-1056 compliant) Based on: https://github.com/uport-project/ethr-did-registry This contract manages decentralized identifiers (DIDs) for vehicles in a gas-efficient manner suitable for V2X applications. Key Features:

- Minimal on-chain storage (gas efficient)
- Event-based DID document construction
- Delegate management for key rotation
- Attribute storage for metadata
- Revocation support (terminal; DIDRevoked carries previousChange so the

did:ethr change list stays walkable through the revocation) Design: no imports, no OpenZeppelin bases. Kept from canonical ERC-1056: `owners`, `changed`, `nonce`, the three DID*Changed events with `previousChange`, the identity-self-owner fallback and the internal (identity, actor, ...) / public (identity, ...) split. Removed: every `*Signed` meta-transaction variant, the `delegates` mapping and `validDelegate` (delegations are event-only here; MOBIVIDRegistry stores them again). Added (CVIN extension): `revoked` / `revokedAt`, `revokeIdentity` + `DIDRevoked`, the `notRevoked` freeze, and the vehicle convenience functions `registerVehicle` / `updateVehicleKey` plus views. Also deployed on its own by the testbed as the "ERC-1056 / vehicle profile" option; in the MOBI group it is the base of MOBIVIDRegistry.

- **standard:** ERC-1056 Ethereum Lightweight Identity https://eips.ethereum.org/EIPS/eip-1056
- **standard:** did:ethr DID method https://github.com/decentralized-identity/ethr-did-resolver/blob/master/doc/did-method-spec.md
- **standard:** W3C DID Core v1.0 https://www.w3.org/TR/did-core/
- **security:** `nonce` is declared but never read or written (no signed variants).
- **security:** No on-chain `validDelegate`: delegate validity must be derived by replaying DIDDelegateChanged events.
- **security:** The vehicle key attribute name is keccak256("did/pub/secp256k1/veriKey/base64"), not the did:ethr ASCII-padded bytes32 name, so a stock ethr-did-resolver does not recognise it as a verification method; the repo's own resolvers match the keccak name.
- **security:** Revocation is owner-only; no authority can revoke an identity.
- **security:** Several changes in one block share one `changed` value; resolvers must take the minimum `previousChange` per block when walking the list.
- **see:** docs/smart-contracts/02-mobi-vid.md
- **see:** sandbox/options/erc-1056-vehicle/ (standalone adapter)

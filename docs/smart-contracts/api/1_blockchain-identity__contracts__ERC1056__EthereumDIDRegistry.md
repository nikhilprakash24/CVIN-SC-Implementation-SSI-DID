## contract `EthereumDIDRegistry`

**EthereumDIDRegistry** · CVIN research project (Solidity 0.8 port of uPort / DIF ethr-did-registry)

Single shared contract for all DIDs (did:ethr method)

*Dev:* ERC-1056 Lightweight Identity Registry. Gas-efficient, event-based architecture with minimal on-chain storage. Near-verbatim port of the upstream registry; no inheritance, no imports, no OpenZeppelin dependency. Owner/delegate/attribute changes are emitted as events chained through `previousChange`; off-chain resolvers walk `changed[identity]` -> `previousChange` to rebuild the DID Document. Based on: https://github.com/uport-project/ethr-did-registry EIP: https://github.com/ethereum/EIPs/issues/1056 Features:

- Implicit DID creation (any Ethereum address is a valid DID)
- Off-chain DID Document resolution via events
- Temporary delegates (time-bound verification keys)
- Flexible attributes (service endpoints, custom properties)
- Meta-transactions (gasless operations via signatures)
- Minimal gas costs (events only, no storage for attributes)

- **standard:** ERC-1056 Ethereum Lightweight Identity, https://github.com/ethereum/EIPs/issues/1056
- **standard:** did:ethr DID method, https://github.com/decentralized-identity/ethr-did-resolver/blob/master/doc/did-method-spec.md
- **standard:** W3C DID Core v1.0, https://www.w3.org/TR/did-core/
- **standard:** ERC-191 signed data (version 0x00 layout, raw digest), https://eips.ethereum.org/EIPS/eip-191
- **security:** `block.timestamp + validity` is checked arithmetic: validity = type(uint256).max reverts (panic 0x11), cf. defect D18.
- **security:** Signed digests contain no chainid, so signatures replay across chains with the same registry address; the nonce is per owner and shared across all identities that owner controls.
- **security:** Attributes exist only as events; no contract can read an attribute value on-chain.
- **security:** changeOwner(identity, address(0)) deactivates the DID for did:ethr resolvers, yet identityOwner then returns `identity` again, so the original key regains on-chain control (inherited from upstream).
- **security:** No identity-level revocation and no guardians/recovery; revocation is per delegate and per attribute.
- **security:** Delegates carry no on-chain authority; integrators must call validDelegate themselves.
- **see:** docs/smart-contracts/01-erc1056-did-registry.md
- **see:** sandbox/options/erc-1056-uport/adapter.js

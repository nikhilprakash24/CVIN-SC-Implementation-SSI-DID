## contract `CVINVehicleNFT` is `ERC721`, `ERC721URIStorage`, `ERC721Enumerable`, `AccessControl`

**CVINVehicleNFT** · CVIN research project

Each NFT represents a unique vehicle identity Features:

- VIN-based vehicle identity
- Ownership tracking via NFT ownership
- Complete transfer history on-chain
- Vehicle metadata stored on IPFS
- DID resolution (did:nft:erc721:{contractAddress}:{tokenId})
- Role-based access (manufacturers, inspectors, service centers)
- Enumerable for efficient queries

Design: built on OpenZeppelin Contracts 5.0.2 (ERC721, ERC721URIStorage, ERC721Enumerable, AccessControl, Strings). Sequential tokenIds start at 1 (0 = "no token" sentinel in vinToTokenId). The constructor grants DEFAULT_ADMIN_ROLE and MANUFACTURER_ROLE to the deployer. Revocation is a soft `active=false` flag (deactivateVehicle); there is no burn path. Deviations from plain ERC-721: none at the interface level; the CVIN extensions (VIN maps, metadata struct, transfer history, service records, did:nft string) are additive. `_setTokenURI` (OZ 5.0.2) emits the EIP-4906 MetadataUpdate event, but EIP-4906 is not declared by this contract.

*Dev:* ERC-721 based Vehicle Identity with DID integration

- **standard:** ERC-721 Non-Fungible Token (core, Metadata, Enumerable) https://eips.ethereum.org/EIPS/eip-721
- **standard:** ERC-165 Standard Interface Detection https://eips.ethereum.org/EIPS/eip-165
- **standard:** W3C DID Core (did:nft is not a registered DID method) https://www.w3.org/TR/did-core/
- **security:** Fixed: mintVehicle used to call _safeMint (onERC721Received on a contract recipient) before writing the VIN index, so a MANUFACTURER_ROLE receiver could re-enter and mint the same VIN twice. The VIN maps are now written first; metadata is still written after the callback (getVehicleMetadata reads empty inside it).
- **security:** No burn: a deactivated vehicle can still be transferred and still receive service records (neither path checks `active`).
- **security:** transferHistory and serviceRecords are unbounded arrays; the whole-array getters can exceed view gas limits for long histories.
- **security:** INSPECTOR_ROLE is granted by grantInspectorRole but no function checks it. Service records are unsigned free-form strings.
- **security:** The did:nft contract address is lower-case hex, not EIP-55 checksummed.
- **see:** docs/smart-contracts/03-token-standards-erc721-erc1155-lsp8.md
- **see:** sandbox/options/erc-721/adapter.js (the sandbox adapter wraps only this ERC-721 contract)

#### `mintVehicle`

```solidity
function mintVehicle(address to, string vin, string make, string model, uint16 year, string color, string metadataURI) external onlyRole returns (uint256)
```

Mint a new vehicle NFT (manufacturer only)

*Dev:* Access: MANUFACTURER_ROLE. Normalises the VIN (ISO 3779, D13), requires it to be unique and `to != address(0)`, writes the VIN maps, `_safeMint`s, sets the token URI, writes the metadata and pushes a mint TransferRecord. Emits Transfer, MetadataUpdate (OZ URIStorage) and VehicleMinted. CVIN extension wrapping the ERC-721 mint.

- **security:** The VIN maps are written before _safeMint's onERC721Received callback, so the callback cannot mint the same VIN again; metadata is written after it.

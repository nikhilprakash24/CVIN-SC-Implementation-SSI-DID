## contract `CVINVehicleDIDRegistry`

**CVINVehicleDIDRegistry** · CVIN research project

Provides convenience functions for vehicle identity lifecycle

*Dev:* Vehicle-specific DID management using ERC-1056 (CVIN extension). Holds a reference to an EthereumDIDRegistry (composition, no inheritance, no OpenZeppelin). Two modes: direct mode (the owner calls the registry itself; this contract only holds the VIN<->DID index) and wrapper-controlled mode (the owner calls didRegistry.changeOwner(did, address(this)); the wrapper then tracks the vehicle owner in vehicleOwners and forwards attribute/delegate writes). Identity model: DID = the vehicle owner's address. Features:

- VIN-to-DID mapping
- Vehicle-specific attributes
- Ownership transfer tracking
- Service history references
- Credential issuance delegation

- **standard:** ERC-1056 Ethereum Lightweight Identity, https://github.com/ethereum/EIPs/issues/1056
- **standard:** did:ethr DID method, https://github.com/decentralized-identity/ethr-did-resolver/blob/master/doc/did-method-spec.md
- **standard:** W3C DID Core v1.0, https://www.w3.org/TR/did-core/
- **standard:** ISO 3779 Vehicle Identification Number (17 characters), https://www.iso.org/standard/52200.html
- **security:** No way back: no function returns ERC-1056 control via changeOwner, so a DID handed to the wrapper stays locked in it (no key rotation, no signed operations).
- **security:** createVehicleDID binds an arbitrary address without the owner's consent; a second VIN for the same address overwrites didToVIN but leaves the old vinToDID entry.
- **security:** DID is conflated with the owner address: a direct-mode transfer re-keys the VIN to a different DID, so the vehicle identifier is not stable.
- **security:** The VIN is stored and emitted in plaintext (didToVIN, VehicleDIDCreated).
- **security:** Attribute and delegate keys are keccak256 hashes of names, not did:ethr-conformant names.
- **security:** No revokeAttribute passthrough: a service endpoint set in wrapper mode cannot be revoked.
- **see:** docs/smart-contracts/01-erc1056-did-registry.md
- **see:** sandbox/options/erc-1056-uport/adapter.js

```solidity
function updateOwnershipMapping(address oldOwnerDID, address newOwnerDID) external
```

Transfer vehicle ownership

*Dev:* In ERC-1056, the owner must call didRegistry.changeOwner() directly. This function updates the VIN mapping after ownership transfer. CVIN extension, direct mode. Callable by anyone: the only check is identityOwner(oldOwnerDID) == newOwnerDID. Moves the VIN to newOwnerDID and emits VehicleOwnershipTransferred(old, old, new).

- **note:** The in-body comment "Verify caller is the new owner" is stale: msg.sender is not checked. That is safe: the result is fixed by the ERC-1056 owner's own changeOwner, so any caller can only perform the sync it already authorised (a permissionless follow-up, not a takeover).

## contract `MOBIVIDRegistryV2` is `MOBIVIDRegistry`

**MOBI VID Registry V2** · CVIN research project

MOBI VID II lifecycle events: role-gated event issuance with VC hashes and multi-party, owner-consented, EIP-191-signed attestations.

*Dev:* Extends MOBI VID Registry with VID 2.0 lifecycle events Standards Compliance:

- MOBI VID I (Vehicle Birth Certificate) - from base contract
- MOBI VID II (Lifecycle Events) - NEW
- W3C Decentralized Identifiers (DIDs) v1.0
- W3C Verifiable Credentials v1.1
- ERC-1056 (Ethereum DID Registry)
- SSI (Self-Sovereign Identity) principles

Key Features:

- Lifecycle event tracking (maintenance, accidents, recalls, etc.)
- Multi-party event issuance
- Event attestations from multiple signers
- Role-based access control for issuers
- Verifiable Credential integration
- Complete vehicle history

Design: `MOBIVIDRegistryV2 is MOBIVIDRegistry is ERC1056Registry`. Imports OpenZeppelin Contracts 5.0.2 `ECDSA` and `MessageHashUtils` (libraries, not bases). The role => event-type matrix is fixed at deploy by _initializeAllowedIssuers (no setter). Deviations from the repo's MOBI_VID2_SSI_DESIGN.md: no OWNERSHIP_TRANSFER event type (ownership uses transferVehicleOwnership), REGISTRATION and DECOMMISSION added, IssuerRole has NONE, and attestations live in `eventAttestations[eventId]`. The VC integration is only the opaque `credentialHash`; no VC is parsed on-chain.

- **standard:** MOBI Vehicle Identity (VID II) https://dlt.mobi/standards/
- **standard:** ERC-1056 Ethereum Lightweight Identity https://eips.ethereum.org/EIPS/eip-1056
- **standard:** EIP-191 Signed Data Standard https://eips.ethereum.org/EIPS/eip-191
- **standard:** EIP-2 (low-s signatures, via OpenZeppelin ECDSA) https://eips.ethereum.org/EIPS/eip-2
- **standard:** W3C Verifiable Credentials Data Model v1.1 https://www.w3.org/TR/vc-data-model/
- **standard:** W3C DID Core v1.0 https://www.w3.org/TR/did-core/
- **security:** Issuer roles are registry-wide (one role per address); organisational roles can file events against any vehicle by design. OWNER is scoped at use time to the current owner (K-15).
- **security:** Lifecycle events are append-only: they cannot be revoked or corrected, and de-authorising an issuer does not invalidate past events. DECOMMISSION / THEFT_REPORT do not freeze the identity.
- **security:** Odometer values are not checked for monotonicity on-chain (rollback detection is off-chain).
- **security:** getEventsByType / getOdometerHistory are unbounded loops (fine for eth_call only).
- **security:** Attestation signatures use ad-hoc domain separation (contract, chainid), not EIP-712, and are stored on-chain after verification (gas cost).
- **security:** `jurisdiction` is a free-form, unvalidated string.
- **see:** docs/smart-contracts/02-mobi-vid.md
- **see:** sandbox/options/mobi-vid/adapter.js

#### `attestEvent`

```solidity
function attestEvent(bytes32 eventId, address vehicleIdentity, bytes signature) external
```

Attest to an event

*Dev:* Allows multiple parties to sign off on an event The attester must sign the domain-separated attestation digest keccak256(abi.encodePacked( address(this), block.chainid, vehicleIdentity, eventId)) wrapped with the EIP-191 ("\x19Ethereum Signed Message:\n32") prefix. The signature is recovered on-chain and MUST match msg.sender. SECURITY (before/after): earlier revisions stored `signature` verbatim and NEVER verified it on-chain (no ecrecover) — the call was gated only by the attester's role, so any role-holder could record a garbage or forged attestation signature (a replay/forgery gap). This revision binds the signature to this contract, this chain, the vehicle and the event, and rejects anything that does not recover to the attester. Access: the event must exist, the caller must hold a role other than NONE, and must be the current owner or a valid bytes32("veriKey") delegate of the vehicle (D54; a sigAuth delegation does not count), and may attest once. Emits EventAttested.

- **note:** hasAttested is set before the signature check; a revert rolls it back.

| Parameter | Type | Description |
|---|---|---|
| `eventId` | `bytes32` | Event to attest |
| `vehicleIdentity` | `address` | Vehicle DID |
| `signature` | `bytes` | EIP-191 signature over the attestation digest, by msg.sender |

## contract `CVIN_SCBasedAccOrID_DID_ERC725Basic`

**CVIN_SCBasedAccOrID_DID_ERC725Basic** · CVIN research project

Basic ERC-725 (v1-era, 2017 "Identity") per-vehicle proxy account. Deploying the contract creates the identity; the deployer becomes the owner.

*Dev:* Interface-shape baseline for the CVIN benchmarks. Self-contained: no imports, no inheritance, no OpenZeppelin (the project pins npm openzeppelin/contracts 5.0.2, unused here). Deviations from ERC-725 v1 / ERC-734:

- Authorisation is a single `_owner` address (inline `require`), not purpose-1

MANAGEMENT keys. Keys are stored but never authorise anything.

- One purpose per key; no `keyHasPurpose`, `getKeysByPurpose` or execution IDs.
- `execute` is a stub that only emits `Executed`; `approve` has an empty body.
- No VIN or data store.

- **standard:** ERC-725 (v1 Identity, superseded by 725X/725Y) https://eips.ethereum.org/EIPS/eip-725
- **standard:** ERC-734 (Key Manager, draft; simplified key model) https://github.com/ethereum/EIPs/issues/734
- **standard:** ERC-173 (ownership-like surface) https://eips.ethereum.org/EIPS/eip-173
- **security:** `execute` performs no call and is not payable; `approve` has no access check and does nothing.
- **security:** `transferOwnership` has no zero-address check.
- **security:** `addKey` on an existing id overwrites the struct and pushes a duplicate into `allKeys`; `removeKey` removes one copy only and emits `KeyRemoved` even for unknown keys.
- **see:** docs/smart-contracts/04-account-claim-identity-erc725-735-4337-combined.md (section 1)
- **see:** sandbox/options/erc-725/adapter.js

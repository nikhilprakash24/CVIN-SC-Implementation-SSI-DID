## contract `MOBIVIDRegistry` is `ERC1056Registry`

**MOBI VID Registry** · CVIN research project

MOBI VID I vehicle birth certificates on a shared ERC-1056 registry: manufacturer-issued births, salted VIN-hash lookup, recorded ownership transfers, on-chain key anchoring and stored delegations.

*Dev:* Implements MOBI Vehicle Identity (VID) 1.0 standard on top of ERC-1056 Standards Compliance:

- MOBI VID I (Vehicle Birth Certificate)
- W3C Decentralized Identifiers (DIDs) v1.0
- ERC-1056 (Ethereum DID Registry)
- SSI (Self-Sovereign Identity) principles

Key Features:

- Immutable vehicle birth certificates
- VIN privacy protection (hash + encrypted storage)
- Manufacturer authorization system
- Ownership transfer with complete history
- W3C DID compliance
- Gas-optimized storage

Design: `MOBIVIDRegistry is ERC1056Registry`; no OpenZeppelin bases. MOBI VID I/II are consortium documents with no Solidity ABI, so every interface here is the repo's own MOBI profile (CVIN extension). Deviations from the repo's MOBI_VID1_TECHNICAL_SPEC.md draft: `lookupByVINHash` (not findVehicleByVINHash), finite PERMANENT_ATTRIBUTE_VALIDITY instead of the overflowing type(uint256).max, `VehicleBirth.blockNumber`, and the K-3/K-4/ D11b/D54 changes. Restores canonical ERC-1056 delegate storage and `validDelegate`, and blocks the plain `changeOwner` for born vehicles.

- **standard:** MOBI Vehicle Identity (VID I / VID II) https://dlt.mobi/standards/
- **standard:** ERC-1056 Ethereum Lightweight Identity https://eips.ethereum.org/EIPS/eip-1056
- **standard:** W3C DID Core v1.0 https://www.w3.org/TR/did-core/
- **standard:** did:ethr DID method https://github.com/decentralized-identity/ethr-did-resolver/blob/master/doc/did-method-spec.md
- **security:** Birth and manufacturer-path key attributes are written with the owner as ERC-1056 actor without the owner's signature, so the event looks owner-authored though the manufacturer sent it.
- **security:** Vehicle identities are key-less addresses chosen by the manufacturer (derived from the VIN by callers); control exists only through `owners[]`.
- **security:** The registering manufacturer can still anchor the first key after its authorisation is revoked (anchorVehicleKey checks vehicleBirths[id].manufacturer, not authorizedManufacturers).
- **security:** Single-EOA registry authority, auto-authorised as manufacturer; one-step hand-over with no event.
- **security:** `encryptedVIN` is public ciphertext; confidentiality rests on the off-chain AEAD. The VIN-hash formula is not enforced (some callers use an unsalted keccak256(vin), which is dictionary-attackable).
- **security:** Revocation is inherited: owner-only and terminal; no authority can decommission a vehicle.
- **see:** docs/smart-contracts/02-mobi-vid.md
- **see:** sandbox/options/mobi-vid/adapter.js (wraps MOBIVIDRegistryV2)

#### `anchorVehicleKey`

```solidity
function anchorVehicleKey(address vehicleIdentity, bytes publicKey) external vehicleRegistered notRevoked
```

Publish the vehicle's secp256k1 verification key with vehicle-lifetime validity.

*Dev:* Anchor the vehicle's verification key on-chain as a DIDAttributeChanged event with the vehicle-lifetime validity, so that a verifier holding no off-chain registration record can still resolve the key that signs the vehicle's V2X messages (defect D11b: before this the key was generated off-chain after the birth and never published). Who may anchor:

- the current identity owner, at any time (a rotation with lifetime

validity; updateVehicleKey remains the 1-year variant);

- the manufacturer that registered the birth, exactly once and only

while the vehicle has never changed hands — the birth session. After the first sale only the owner can publish keys, so the manufacturer holds no standing power over a vehicle it no longer controls. The attribute is written with the identity owner as the ERC-1056 actor, exactly as the birth attributes are, preserving the base invariant that attributes are owner-authored. CVIN extension. vehicleRegistered, notRevoked. Accepts a 65- or 33-byte secp256k1 key. Emits DIDAttributeChanged and VehicleKeyAnchored.

| Parameter | Type | Description |
|---|---|---|
| `vehicleIdentity` | `address` | The vehicle identity |
| `publicKey` | `bytes` | Uncompressed (65-byte) or compressed (33-byte) secp256k1 public key |

**Returns:** DID string in format: did:ethr:0x{chainId hex}:0x{40 lowercase hex} The chain id is the minimal (unpadded) lowercase hex of block.chainid with a 0x prefix, as the did:ethr method specification writes it; the address is the 0x-prefixed, zero-padded 40-hex-char form.

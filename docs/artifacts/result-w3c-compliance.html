W3C Compliance — DID + VC Conformance

w3c_compliance.json · 44 executed checks · DID Core v1.0 + VC Data Model v2.0

Aggregate conformance of the DID resolver and the Verifiable-Credential stack against the W3C DID Core v1.0 and VC Data Model v2.0 specifications. Direct evidence for H2: ≥90% aggregate W3C compliance is achievable through a resolution/translation layer.

What it measures
Per-requirement PASS / PARTIAL / FAIL status across DID Core and VC DM, scored as (PASS + 0.5×PARTIAL) / executed checks. Ten qualitative SSI-principle checks are recorded but excluded from the score.
Method
Every non-qualitative check actually executes the DID resolver and VC stack and records the observed outcome (resolved documents, rejection errors, verifier verdicts). A snapshot of w3c_compliance_checker.py.
Key numbers
44 executed checks — 40 pass, 2 fail, 2 partial — for an aggregate 93.2%. By spec: DID Core 93.3% (13 PASS + 2 PARTIAL of 15) and VC DM 93.1% (27 PASS of 29). Residual gaps are confined to specific properties (e.g. methodNotSupported error code, placeholder key material) rather than structural failures.
Source file
4_comparison-framework/results/w3c_compliance.json (snapshot of 2_w3c-ssi-layer/.../w3c_compliance_checker.py)
Provenance / caveat
Produced by the researcher's compliance checker. Caveat (§4.6): 93.2% is measured against our reading of the spec in a self-authored checker — it is presented explicitly as a self-assessment. The strengthening fix is to run the official W3C VC/DID conformance vectors and report agreement.
Confirms H2

Aggregate compliance is 93.2% (DID Core 93.3% / VC DM 93.1%), clearing the 90% target with gaps confined to named properties. Reported honestly as a self-assessment: the checker grades our own reading of the spec, pending external conformance-vector agreement. (Results §5.5; RESEARCH_AUDIT §4.6.)

V2V Latency — Credential Verification (N=30)

v2v_latency_stats.json · N=30 seeded runs · 50 veh × 20 s · SSI vs PKI · perf_counter

Per-message identity-verification latency for an SSI stack (W3C VC + secp256k1 EIP-191) against an IEEE 1609.2-style PKI baseline (ECDSA P-256), across a simulated V2V message flow. Direct evidence for H3: off-chain verification of pre-issued credentials meets the V2V budget.

What it measures
Sign / cold-verify / warm-verify latency (milliseconds) for the SSI and PKI populations, reported as the median of per-run medians with a 95% CI and p95, over 30 independent seeded runs of 50 vehicles × 20 s each.
Method
Each run is an independent subprocess of sumo_identity_integration.py --simulate (real ECDSA P-256 for PKI, real W3C VC + secp256k1 for SSI; time.perf_counter). Seeds 1..30 drive mock highway mobility; the 95% CI of the median is a percentile bootstrap (10,000 resamples). Totals are summed across all runs.
Key numbers
SSI warm-verify median 0.165 ms (95% CI [0.162, 0.168]); PKI warm 0.102 ms; SSI cold 0.400 ms. Across the run, 1,650,318 verifications (≈1.65M) were performed with exactly 90 failures — the 3 injected attacks × 30 runs, zero benign-flow failures.
Source file
cv2x-testbed/sumo/results/v2v_latency_stats.json (+ raw v2v_latency.json)
Provenance / caveat
Produced by cv2x-testbed/sumo/run_v2v_stats.py. Caveat (§4.4): these are pure identity-verification CPU times — radio/MAC contention, propagation, queuing, and application processing are excluded (no network stack; mock mobility; single host). The CI is a repeatability interval, not population inference (§4.5).
Supports H3

SSI credential verification runs in 0.165 ms warm (95% CI [0.162, 0.168]) over 1.65M verifications — the 90 failures are exactly the injected attacks, so the benign flow never mis-verifies. The defensible claim is narrow: credential verification is not the bottleneck. This figure excludes the network stack and is not an end-to-end V2V latency (§4.4). (Results §5.4.)

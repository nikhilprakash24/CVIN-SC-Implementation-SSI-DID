MOBI VID II — Lifecycle Events

MOBI Vehicle Identity · 11 event types · multi-party attestation · ecrecover-verified

The post-birth history model: 11 lifecycle event types, each issued as a signed W3C Verifiable Credential and anchored on-chain, plus multi-party attestation. The on-chain attestEvent now verifies the attester's signature via ecrecover — a found-and-fixed security gap.

What it is
The MOBI Vehicle Identity lifecycle model: 11 event types (maintenance, repair, accident, recall, inspection, modification, theft report, recovery, insurance claim, registration, decommission), each a signed VC anchored by credentialHash, with role-gated issuance (NONE + 8 issuer roles) and third-party attestations.
Reference
dlt.mobi — MOBI Vehicle Identity (VID)
Role in thesis
The lifecycle-event and attestation half of the MOBI-VID application profile, and the site of a found-and-fixed on-chain security finding. The Python enums mirror MOBIVIDRegistryV2.sol exactly (the contract is the source of truth).
Where used
2_w3c-ssi-layer/mobi-vid/lifecycle_events.py, 1_blockchain-identity/contracts/MOBI/MOBIVIDRegistryV2.sol
Provenance
Implemented and audited by the researcher. The security audit exposed that attestEvent stored an attestation signature it never verified; the researcher added on-chain ecrecover over a domain-separated digest binding contract address, chainId, vehicle, and eventId (blocking forgery and cross-context replay), with a before/after regression test. See PROVENANCE.md.
Found & fixed

Before the fix, attestEvent stored an attestation signature that was never verified on-chain — a forgery/replay gap gated only by attester role. Adding ecrecover over the domain-separated digest closes it; the attestation cost rises from 121,110 to 192,718 gas as the price of real on-chain verification, and the MOBI Replay security test now passes. (Security §5.6.)

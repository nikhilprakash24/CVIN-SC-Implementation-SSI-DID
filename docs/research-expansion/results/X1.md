# Results — X1 Toll Corridor (WP 0.1)

**Date:** 2026-10-15 · **Status:** CLOSED (built and tested); numbers are proposed register rows, not V status.

## What was built
- `1_blockchain-identity/contracts/Scenarios/CVINTollCorridor.sol`. It provides:
  - EIP-712 issuer endorsements bound to an off-chain VC by `credentialHash`;
  - EIP-712 vehicle tickets signed by the ERC-1056 owner or any live `veriKey` delegate;
  - an EIP-2612-funded stablecoin escrow;
  - a one-bit revocation per endorsement, and a per-identity nonce set;
  - `checkTicket` (read) and `payToll` / `settleBatch` (write) sharing one code path.
- `CVINTestStable.sol`: a test-only 6-decimal permit token.
- `test/Scenarios/TollCorridor.test.js`: 20 tests (5 happy paths, 14 attack cells, 1 gas profile).
- `cv2x-testbed/scenarios/toll_corridor.py` and `cv2x-testbed/tests/test_x1_toll_corridor.py` (4 tests): a mixed SSI/legacy fleet with DMV-sponsored pseudonyms.
- `cv2x-testbed/results/x1_toll_corridor.json`.

## Findings
1. **Split-brain revocation.**
   - An off-chain registration suspension is caught only by the VP check (`vp_invalid`).
   - An on-chain endorsement revocation is caught only by `checkTicket` (code 7).
   - A gate needs both checks. Candidate H6 / SP-10.
2. **Rotation is not unlinkability.**
   - Every ticket and every `TollPaid` event carries the DID address, so trips link across gantries even though the signing pseudonym rotates.
   - This agrees with register #38 from the application side. It motivates P5 (H8).
3. **Exposure.**
   - The SSI lane reveals the DID address, the pseudonym address, the vehicle class and the jurisdiction. It never reveals the VIN or the plate.
   - The legacy lane reveals the plate, an image, and the time and place.
   - No legacy latency is reported, because no ANPR model is run.

## Caveats
- The vehicle class in the VP is checked against the on-chain endorsement class. A ministry that signs a VC and an endorsement that disagree is an issuer fault, outside threat model T2.
- `settleBatch` is all-or-nothing. A gantry is expected to pre-screen with `checkTicket`.
- There is a single authority, no dispute window and no upgradeability. This is research scaffolding.

## 2. The machine, in one paragraph

The testbed is an engine with one working fluid, a signed message, and one output, a trust decision per message.
Identity is manufactured on the ledger (DWG-002), expressed as a credential (IF-03), carried with the message
(IF-05, IF-06), and consumed by the verifier (DWG-003) whose governor (DWG-004) decides how often the chain is
consulted. Everything the engine produces is weighed on the evidence line (DWG-005) before it is reported, and the
envelope within which the engine is claimed to hold is the threat model (DWG-006). The planes (DWG-001) are the
casing: a plane depends only on the planes below it and on the evidence plane, which depends on none.

## 3. Design decisions, with their evidence

| ID | Decision | Alternative rejected | Consequence measured | Sheet |
|---|---|---|---|---|
| DD-01 | One operation catalogue over all substrates; a missing primitive is n/a, never emulated | emulate missing primitives with wrapper contracts | comparability at the cost of "excl. n/a" totals that are not comparable with full totals (#35) | DWG-002 |
| DD-02 | Chain off the hot path: credentials are pre-issued and verified in process; the chain is consulted on a cadence | resolve the sender's key from the chain at message time | warm verify 0.142 ms (#27) against 9.654 ms uncached (#21); staleness of at most k minus 1 messages (#32, #46) | DWG-003, DWG-004 |
| DD-03 | Freshness is signed: the generation time is inside the signed bytes; a bounded replay cache keyed by the digest of the signed bytes | sign the payload only, with the timestamp beside it | a captured packet no longer verifies forever (review-02 T-9); replay inside the window rejected (D29 fixed, #45) | DWG-003 |
| DD-04 | Fields bound to the credential: a SPaT must name the intersection and the RSU its credential names | trust the signature alone | cross-intersection SPaT rejected (D28 fixed; I2 check h, #45) | DWG-003 |
| DD-05 | The probe refresh: one `eth_call` per re-check, full resolution only on change | always resolve fully on refresh | chain cost per refresh 2.758 ms against 10.518 ms (snapshot `t_chain`, #37 and #32, different hosts); the same staleness bound | DWG-004 |
| DD-06 | Exact gas by mode over 36 iterations, with the range beside it; incidental inputs seeded, measured inputs ranged over declared seeds | one iteration per cell | 27 of 110 harness cells vary across iterations, all root-caused (`docs/testing/GAS_CHARTER.md`); I4 reproducible as a range over seeds 1 to 30 (#47) | DWG-002 |
| DD-07 | A result reaches a tracked path only through a promote step that refuses a dirty run | let producers write results directly | `npx hardhat test` no longer rewrites a tracked result (D56); 13 refusal tests in CI | DWG-005 |
| DD-08 | Per-producer code scope for the dirty flag | one whole-tree flag | a run of record names every file it ran (D49); the whole-tree flag is kept beside it as evidence only when clean | DWG-005 |
| DD-09 | Two security lenses: an executable revert suite for G1 to G4, a comparative matrix for G5 to G8 | one scored matrix | 43 of 43 applicable cells revert with the documented reason (#28); the soft goals are scored, not proved | DWG-006 |
| DD-10 | The hybrid (CVIN-Combined) is measured as one candidate among ten, not privileged | present it as the design contribution | dominated by ERC-4337 on all six harness criteria (#36); still on the fidelity-per-gas plane among the MOBI backends | DWG-002 |
| DD-11 | Mock mobility with real cryptography | install SUMO and run real traffic | every message-path figure is reproducible from a seed on any host; none is an end-to-end latency (SC-22) | DWG-001, DWG-003 |

## 4. What the drawings do not show

- No radio, MAC or channel: there is nothing to draw (DWG-001 note 3).
- No public-network ledger: every gas figure is M1 (DWG-001 note 4).
- No RSU-to-RSU path and no MAP content: I2I covers controller to RSU and TMC to controller only (SC-21).
- No SUMO vehicle: mobility is the mock model on every sheet that mentions a message (DWG-003 note 5).
- No criticality numbers on TDP-006: the worksheet carries severities, not rates.

## 5. Regeneration and check

```bash
python3 docs/tdp/make_blueprints.py            # rebuild the six sheets
python3 docs/tdp/make_blueprints.py --check    # CI: byte-for-byte comparison
```

A sheet changes only when its data changes: a new register total, a moved gas cell, a changed source constant, a new
CI job or document check. The regeneration commit names which.

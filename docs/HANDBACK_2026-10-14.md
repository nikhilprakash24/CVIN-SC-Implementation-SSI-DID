## 6. Gotchas (each one cost a pass at least once)
- **Run checks unpiped** and read every exit code; a piped check once hid 43 failures.
- **Run the grand runner last**, then regenerate the snapshot, the dashboard page, the test register and the
  presentation (`make_dashboard_data.py`, `make_dashboard_page.py`, `build_register.py`, `make_presentation.py`);
  the runner rewrites `sandbox/grand/report/*` and CI compares the generated documents.
- **CI checks out full history** (`fetch-depth: 0`) because `check_stamps.py` verifies stamp-only commits from
  history; a shallow clone fails that check by design. Test a check in a `--depth 1` clone before relying on CI.
- **Do not edit `1_blockchain-identity/benchmarks/` casually.** Its tree hash (`benchmarksTree`) identifies the
  harness run of record (conditions §5.F); any edit there waits for the harness re-run (A6, N-19).
- **Every new producer goes into `tools/run_identity/producers.json`** and `stamp.py --write`; name the file that
  actually runs (the security matrix's producer is `securityScenarios.test.js`, not the harness it imports).
- **Producers write to `runs/`** (untracked) and reach a tracked result only through `tools/run_identity/promote.py`;
  it refuses dirty runs, other commits, changed or dirty scopes, edited outputs and undeclared destinations.
- **Quote free text in YAML** (`ideas.yaml`, `process_metrics.yaml`): a ": " inside a value breaks parsing.
- **Pathspecs in any clean-tree check are root-anchored** (`:(top)…`); the probe in CI proves it per producer.
- Stop every node you start by its recorded pid; regenerate tracked testbed artifacts with the root
  `node_modules` (OpenZeppelin 5.0.2) as CI does; always pass `--results <scratch path>` to `sumo_identity_integration.py`.
- A pre-registration is never edited; departures are dated amendments (guide rule 1.2.7).
- Read an item's recorded reason for deferral before folding it into a neighbouring step (pass 14 lesson).
